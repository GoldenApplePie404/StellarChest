# 功能一：场景搭建器（Scene Builder）

## 2. 产品定义

### 2.1 产品目标

1. **降低创作门槛**：让无编程基础的用户通过可视化拖拽即可搭建视觉小说场景，无需手写 `@bg`、`@perform` 等脚本指令。
2. **所见即所得**：搭建场景时实时预览最终效果（背景、角色立绘、对话框），消除「编写→预览」的迭代摩擦。
3. **可导出脚本**：搭建完成的场景配置自动生成对应脚本片段，可直接插入到 Monaco 编辑器中，与现有脚本编辑流程无缝衔接。

### 2.2 用户故事

- **As a** 不会写脚本的新手创作者，**I want** 在可视化界面中拖拽角色立绘到场景中，**so that** 不需要记忆 `@perform` 指令格式即可完成角色站位。
- **As a** 熟练创作者，**I want** 快速试错不同背景和角色搭配组合，**so that** 在正式编写脚本前快速确定场景视觉方案。
- **As a** 脚本编写者，**I want** 将搭建好的场景配置一键导出为脚本片段，**so that** 避免手动抄写指令参数。
- **As a** 编辑器用户，**I want** 从编辑器侧面板直接打开场景搭建器，**so that** 不打断当前的脚本编辑流。

| P0-SB-02 | 背景图选择 | 从已导入资源列表 / 共享素材库中选择背景图，预览图缩略图展示 |

#### 交互说明

1. **左侧资源面板**
   - 顶部 Tab 切换：「背景图」「角色库」「预设模板」
   - 背景图 Tab：网格缩略图展示，点击即应用到画布
   - 角色库 Tab：列出已导入的角色，拖拽到画布放置，支持搜索过滤
   - 预设模板 Tab：列出现有场景模板，点击一键填充

2. **中央场景画布**
   - 使用现有 `GameCanvas.tsx` + `LayerManager` 进行实时渲染
   - 角色立绘在画布上可拖拽到左/中/右吸附位
   - 每个角色上方显示浮层工具栏：[移除] [翻转] [表情切换]
   - 画布底部固定区域为对话框预览

3. **底部属性面板**
   - 点击画布上的角色或背景时，底部面板显示对应属性
   - 角色属性：位置选择、缩放滑块、翻转开关、表情下拉
   - 背景属性：背景ID、过渡效果选择

4. **导出工作流**
   - 点击「导出脚本」→ 弹出预览面板，展示生成的脚本片段
   - 用户可手动编辑后复制，或直接「插入到编辑器」
   - 通过 `window.dispatchEvent(new CustomEvent('galgame-insert', ...))` 插入到 Monaco

# 功能二：一键发布与分享（Publish & Share）

## 2. 产品定义

### 2.1 产品目标

1. **一键发布工作流**：用户将项目从「草稿」状态一键发布为「公开作品」，无需复杂配置。
2. **零门槛游玩体验**：访客通过分享链接直接进入游戏，无需登录、无需注册。
3. **作品曝光与社交**：建立公开作品列表页和详情页，让创作者的作品被发现和传播，附带基础统计。

### 2.2 用户故事

- **As a** 创作者，**I want** 在项目编辑完成后一键发布，**so that** 立即生成分享链接发给朋友试玩。
- **As a** 玩家/访客，**I want** 点击分享链接直接开始玩游戏，**so that** 无需注册登录即可体验。
- **As a** 访客，**I want** 在公开作品列表页浏览和筛选已发布的作品，**so that** 发现有趣的 galgame。
- **As a** 创作者，**I want** 查看作品的浏览数和游玩数，**so that** 了解作品的受欢迎程度。
- **As a** 创作者，**I want** 更新已发布的作品或取消发布，**so that** 修复 bug 或下架不满意内容。

### 2.3 需求池

# 功能三：剧情分支流程图（Branch Timeline）

## 2. 产品定义

### 2.1 产品目标

1. **可视化剧情结构**：自动解析脚本中的 `@label` / `@jump` / `@choice` 指令，生成可交互的节点-连线图，帮助创作者理解剧情分支结构。
2. **编辑-流程图联动**：点击流程图节点跳转到编辑器对应行，脚本编辑时流程图自动刷新，保持实时同步。
3. **分支复杂度管理**：当脚本存在大量分支时，可视化图让创作者一眼看出未连接的死角标签、无效跳转，辅助调试。

### 2.2 用户故事

- **As a** 剧情写作者，**I want** 看到我写的 `@jump` 和 `@choice` 在图上如何连接，**so that** 确认分支逻辑没有写错。
- **As a** 剧情调试者，**I want** 点击流程图节点直接跳转到对应代码行，**so that** 快速定位和修改特定场景。
- **As a** 复杂项目创作者，**I want** 流程图随脚本编辑实时刷新，**so that** 每次保存后都能看到最新的剧情拓扑。
- **As a** 剧情规划者，**I want** 从流程图上一眼看出哪些标签没有被任何 `@jump` 或 `@choice` 引用，**so that** 及时发现孤立场景。

### 2.3 需求池

#### P0 — 必须交付（MVP 核心）

| ID | 需求 | 说明 |
|---|---|---|
| P0-BT-01 | 自动解析流程图 | 解析脚本中的 `@chapter`/`@label` 为节点，`@jump`/`@choice` 为连线 |
| P0-BT-02 | ReactFlow 可视化渲染 | 使用现有 `@xyflow/react` 渲染节点连线图，支持平移/缩放/拖拽布局 |
| P0-BT-03 | 点击节点跳转 | 点击节点触发回调，编辑器滚动到对应行并高亮（已有 `FlowChartView.onNodeClick`） |
| P0-BT-04 | 编辑器侧面板展示 | 流程图作为编辑器右侧/左侧的可切换侧面板（快捷键 Ctrl+Shift+G 已注册） |
| P0-BT-05 | 随脚本编辑实时刷新 | 脚本内容变化时，流程图自动重新解析和渲染，延迟 < 500ms |

#### P1 — 应该交付（增强体验）

| ID | 需求 | 说明 |

#### 侧面板交互

1. **面板切换**
   - 编辑器右侧面板默认显示流程图
   - 可通过底部 Tab 切换「流程图 / 指令速查 / 快捷键」
   - 快捷键 `Ctrl+Shift+G` 切换显示/隐藏

2. **节点交互**
   - 悬停：显示该节点对应的行号和内容预览
   - 单击：编辑器滚动到对应行并添加高亮装饰
   - 双击：在编辑器中选中该行对应的完整指令（方便复制/修改）

3. **实时刷新**
   - 监听 Monaco 编辑器的 `onChange` 事件
   - 内容变化后 300ms 防抖 → 重新解析脚本 → 更新流程图
   - 解析和渲染在 Web Worker 中执行（避免阻塞编辑器）

4. **基于现有 FlowChartView 的增强**
   - 现有 `FlowChartView.tsx` 已实现基础节点/边解析和渲染
   - 增强点：
     - 添加 Dagre 自动布局
     - 添加无效跳转检测（连线红色虚线）
     - 添加孤立标签检测（灰色节点）
     - 添加迷你地图控件
     - 优化节点交互（悬停提示、双击选中）
     - 添加统计面板

## 5. 待确认问题

### 场景搭建器

1. **角色资源来源**：当前 `Asset` 模型中 `character_sprite` 分类是否已存储角色立绘？还是需要从项目本地 `img/` 目录读取？建议两者都支持：优先搜索项目本地文件，其次搜索共享素材库。
2. **Canvas 复用方式**：是直接内嵌 `GameCanvas.tsx`（含完整引擎流程），还是提取一个轻量级的 `ScenePreview` 组件？建议提取纯预览组件以避免引擎副作用。
3. **角色立绘的预设位置**：左/中/右对应 Canvas 的什么坐标？是否基于现有 `LayerManager.renderCharacter` 的 position 参数？建议直接复用，x 坐标比例：left=0.15, center=0.5, right=0.85。
4. **对话框样式**：导出时是否保留用户搭建时的对话框样式设置？还是跟随项目配置中的 `dialogStyle`？

### 一键发布

5. **访客游玩是否需要账号**：P0 要求不登录，但浏览和游玩统计如何防止刷量？建议同 IP 每天计 1 次浏览，每个 session 计 1 次游玩。
6. **已发布项目的资源引用**：发布后项目引用的素材是复制一份快照还是引用原地址？建议发布时锁定 `resourceMap`，防止作者修改素材后已发布作品也变化。
7. **项目打包与部署**：发布的游戏引擎是在当前平台渲染还是需要静态导出？建议当前平台在线渲染，后续再支持静态导出。
8. **作品审核机制**：是否需要审核后再公开？MVP 阶段建议直接公开，后续可加审核。

### 剧情分支流程图

9. **流程图性能上限**：对于数百个节点的大型项目，ReactFlow 性能如何？建议设置节点上限提示（如 >200 节点时提示性能下降）。
10. **Web Worker 解析**：是否需要将 `ScriptParser` 移至 Web Worker 以避免阻塞 UI？P1 阶段实现。
11. **流程图布局算法**：现有简单行列布局在复杂分支下容易混乱，是否引入 Dagre？建议 P1 实现 Dagre 自动布局。
12. **流程图编辑功能**：P2 的「编辑模式」是否值得做？可能减少脚本修改后的同步复杂度，值得评估。
